# JSH Modules LLM Reference

Canonical overview: https://docs.machbase.com/neo/jsh/modules/index.md

JSH modules are built-in standard-library modules. Load them with `require()`; do not install npm packages.

```js
const fs = require('fs');
const os = require('os');
console.println('platform:', os.platform(), os.arch());
```

## Authoring rules

- JSH runs in the Goja runtime, not Node.js or a browser.
- Use `require()`; do not use `import` or `await`.
- Prefer the module API documented by the module metadata instead of assuming Node.js compatibility.
- Keep scripts explicit about file, network, and database side effects.

- `neo://manual/jsh/service`
- `neo://manual/jsh/readline`

The upstream module manual groups built-ins such as `fs`, `os`, `net`, and grouped modules such as `archive/tar`. The complete live module/export metadata is generated by `neo-server/mods/lsp/jsh/service.go` from the runtime module files. The implementation sources are under `neo-server/jsh/lib/` and command modules are under `neo-server/jsh/usr/`.

When a module or export is not present in the current metadata, do not invent it. Read the specific module documentation or inspect the runtime metadata before generating a script.
